Phase 8: Agent — Add Manual Properties
Architecture Note:
Agent does NOT have a separate search/booking engine. For searching & booking (flights, hotels, tours, umrah, visa), the agent visits the public website and books on behalf of customers.

What agent CAN do from their panel is add/edit/delete manual properties (hotels, tour packages, umrah packages) — same forms as admin. Every record saved by an agent has agent_id and added_by = 'agent' stored so admin can track who added what.
New Permissions (added to AgentPermission::ALL_PERMISSIONS)
Perm
bookings.make — Make bookings via public website
Perm
bookings.view — View own bookings in agent panel
Perm
hotels.add — Add / edit / delete manual hotels
Perm
tours.add — Add / edit / delete tour packages
Perm
umrah.add — Add / edit / delete umrah packages

Routes Summary
# hotels.add permission gates:  GET/POST /agent/hotels, GET/PUT/DELETE /agent/hotels/{id}
# tours.add  permission gates:  GET/POST /agent/tours,  GET/PUT/DELETE /agent/tours/{id}
# umrah.add  permission gates:  GET/POST /agent/umrah,  GET/PUT/DELETE /agent/umrah/{id}
# bookings.view gates:          GET /agent/bookings, GET /agent/bookings/{type}/{id}
Admin visibility
Note
In admin's hotel/tour/umrah list views, show an "Agent" badge next to records where added_by = 'agent', with the agent's name (join on agent_id → users.name). Admin sees everything; agent sees only their own records.
